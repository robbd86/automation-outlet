Siemens S7-300 SF & BF lights: what to check first

A red fault LED doesn't automatically mean a faulty CPU. Use the LED pattern and diagnostic information to narrow down the reason before swapping expensive modules or restarting a stopped machine.

Follow the checksAll engineering guides
Scope and safety: This is general fault-finding guidance for trained personnel, not a substitute for the manual for your exact CPU order number or your site's electrical safety procedure. Isolate where required. Do not disconnect field wiring, move mode switches, reset fault states or load a PLC programme as a speculative fix. Protect personnel and machinery before any intervention.

What do the fault indicators mean?

IndicatorWhat it suggestsUseful next check
SF (system fault)A detected hardware, software, I/O, parameter or system diagnostic issue. It does not by itself identify the faulty component.Read the CPU diagnostic buffer and inspect diagnostics of the affected rack/modules.
BF / BUSF (bus fault)Communication problems on a supported interface, often PROFIBUS or PROFINET depending on the CPU variant.Identify which interface shows the fault, affected station, network status and its configured address.
STOPThe CPU is not executing the user programme. Cause varies: deliberate stop, fault handling, start-up or missing resources.Use operating-mode and diagnostic-buffer evidence, not only the LED.
FRCEAn active force can exist on models that support the indicator.Check authorised forcing status and follow your site's change control. Never remove forces blindly.

LED labelling and behaviour vary by CPU generation. On some S7-300 models the bus indication is called BF1/BF2; on others BUSF. Consult the matching Siemens CPU manual.

A useful six-step diagnostic sequence

  1. Capture the state. Note the exact 6ES7 CPU number and all LEDs, including whether RUN or STOP is active. Photograph the rack before touching connectors.
  2. Establish what changed. Did this follow a panel intervention, power interruption, I/O replacement, cable damage, software download or machine washdown? Note which drives/HMIs remain online.
  3. Go online without changing the programme. With authorised STEP 7 access, open the CPU/module diagnostics and read the diagnostic buffer. Record the first event in the incident and the events immediately before and after it. The newest entry appears first in Siemens' buffer.
  4. Follow the evidence. SF plus a module diagnostic directs attention to that module and its power/wiring/configuration. BF plus a missing station directs attention to network health, power to the station and addressing. Do not infer a dead CPU from a red LED alone.
  5. Check affected hardware safely. Under an approved isolation and test plan, inspect field supplies, diagnostic LEDs, cable/connector condition, terminations and physical damage. Compare actual module part numbers with the configured hardware.
  6. Record the resolution. Retain diagnostic extracts, changes made and a restart plan. If replacement is necessary, verify hardware revision, firmware, memory card, programme backup and communications compatibility first.

Common scenarios worth separating

BF after work near a cabinet

Review recent wiring work and which slave is unreachable. In an authorised safe condition, inspect power, cable routing, shielding, connectors and termination for that segment.

SF with the CPU still in RUN

Not every system diagnostic forces STOP. Read module and CPU diagnostics before assuming the processor itself is defective.

SF and STOP after programme work

Review the diagnostic buffer for programme/runtime, configuration or module mismatch events. Avoid repeated resets before preserving evidence and backups.

Before ordering a replacement S7-300 CPU

Record the full 6ES7 catalogue number and suffix, firmware/hardware revision, MMC details, slot/rack, configured communication interfaces and programme availability. A similar-looking CPU is not automatically interchangeable.
